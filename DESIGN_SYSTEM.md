# Jharkhandi Civic Ledger  — Design System

## Design principle

The interface should feel like a public-interest decision instrument, not a generic startup dashboard. Evidence, reviewability, hierarchy and calm reading rhythm take priority over decoration.

## Visual language

- Paper canvas: warm off-white rather than pure white/grey.
- Forest: authoritative primary action and active navigation.
- Rust: sparing editorial emphasis and decision markers.
- Serif display typography: civic/editorial hierarchy.
- System sans: operational content, forms and controls.
- Monospace micro-labels: case IDs, statuses, stages and audit language.
- Ruled grids: data cells and workflows instead of floating card collections.
- Minimal radius: 3–8 px for a deliberate, instrument-like character.
- Minimal shadow: separation is primarily created through rules, tone and spacing.

## Public website

The first fold pairs an editorial statement with an evidence/decision dossier. Down-page systems use ledger indexes, ruled workflows, dark intelligence reading room, stakeholder profiles and an interface language panel.

## Workspaces

The application shell uses a light civic ledger rail, quiet command bar, briefing-sheet role overview and dense but readable data surfaces. Role color remains semantic and is used for current state / primary action rather than decoration.

## Mobile

Mobile keeps one vertical document scroll owner. Navigation becomes an edge-to-edge dock, forms keep 16 px inputs, role statistics stack 2×2, and long workflow rails scroll horizontally without stealing the vertical gesture.
